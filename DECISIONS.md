# Decisions
- Python 3.12, uv, setuptools; Pydantic v2, httpx, FastAPI; pytest/asyncio, ruff, strict mypy.
- All budgets constrain tokens, dollars and elapsed compute together; defaults 4096 tokens, $0.10, 60 seconds. Conservative adapter reservation must fit before a call starts.
- Default model fake for reproducible offline development. Real model prices and ladders are configuration, never token-cost constants.
- Human edit floors require at least 30 samples per partition; ship 200-row synthetic replay fixtures.
- Only explicit `cheapest that passes` invokes the ladder; otherwise honor model_target.
- Runtime delivery loads the authenticated artifact entrypoint from disk; it never accepts an unrelated caller-supplied harness.
- Report integrity uses local persisted HMAC authority. Protects against forged data and artifact mutation, not hostile code in the trusted Python process.
- Telemetry uses closed categories or deterministic hashed identifiers, not arbitrary short strings. Source content stays solely in artifacts/fixtures.
- Lifecycle names follow source spec: install / expire. Approval required for inferred install specs.
- Pin @mariozechner/pi-coding-agent, pi-agent-core and pi-ai to 0.73.1 with committed npm lockfile. Use actual SDK types (tools is string[]), a real Pi subprocess, and fake provider stream for offline end-to-end tests; see docs/research.md.
- Official ARC SDK arc-agi 0.9.9 exists (Python >=3.12). Ship an explicit optional official adapter plus three clearly labeled local test games; never silently substitute toy results for official scoring.
- Offline ARC model assumption: qwen3:4b via Ollama, configurable; fake adapter for deterministic tests. No submission compliance claim pending rules.
- Held-out access uses an identity capability retained outside tuning data; only Stage 4 imports it in production. Trusted host code owns the gate; proposed rewrites will not run in the host process.
- Grid sizes are small (at most three tunables per launch preset) to keep synthetic compile checks bounded. LLM-judge calibration mean absolute error tolerance defaults to 0.15 and is explicit configuration.
- Presets honor explicit output schemas. Planner/verifier string schemas permit prose; schema validity is not semantic quality, which the floor must test. Coder Phase2 is only a marked pi-pack.json interface plus guarded smoke, replaced by real Pi in Phase5.
- Compilation has a nested aggregate wallet: default $10 and 120s, configurable. Individual agent run budgets still apply independently; fixed-judge model calls share the compile wallet. The later user override removed the former token allowance; tokens are usage metrics only.
- Stage3 rewrite cap defaults to3; model ladder is JSON config and runs only for the exact target "cheapest that passes". All passing rungs are compared by measured cost.
- Inference defaults: $1 and 30s, within the aggregate compile wallet. Input/response protocol size is bounded to 65,536 characters. Former product token allowances and output token clips were removed by the user override; provider-required capacity fields are technical limits only.

- Phase4 rewrite sandbox is a closed AST capability language plus subprocess, not arbitrary Python guarded by a blacklist. Only guarded model calls and the validated preset execution seam are capabilities; unsupported rewrites are rejected. Source64KiB/AST2000/protocol128KiB/calls64. Rewrites need an explicit fixed smoke provider and default cap3.
- Stage3 positive-dollar acceptance requires strict mean-cost reduction against observed baseline spend; partial failed-run spend is a lower bound, never invented full usage. Zero-dollar baselines may improve token demand.
- Registry default drift window10, warning margin0.05; successful reuse promotion3; two cumulative failed verifications evict. Install acceptance prioritizes quality, then signed mean dollars, then components; exact ties do not ship.

- User clarification: ship a first-class CLI agent-factory experience. `architect do <goal> --repo ...` delegates through bespoke compiled Pi agents, never a second coding loop. `architect create <feature> --repo ...` uses a compiled builder agent to request/compile/integrate the feature agent. Nested creation uses the same verification authority, aggregate budgets and install approval; no builder may self-license or invent trusted evaluation data. Lower-level compile/run/status/recompile commands remain useful.

- User requests Claude Code CLI Opus5.5 agents for development and verification. Installed CLI2.1.282 has active local authentication; request exact claude-opus-5-5 and confirm returned model before claiming use. Read-only review launched with only Read/Glob/Grep, no permission bypass, capped$5. Product backend remains real Pi.
- Claude Code CLI model check returned an actual assistant response with model claude-opus-5-5. Read-only review output saved under ignored .architect/; model availability is confirmed, not inferred from an alias.
- Drift telemetry distinguishes primary/secondary with a closed floor_role enum; separate rolling windows prevent a strong secondary signal masking a primary breach.
- ClaudeCLI review accepted: automatic replacement cannot relax any installed budget ceiling; only an explicit trusted manual allowance can. Registry drift starts at current activation time, excluding pre-install compilation evidence and resetting derived windows on rollback.

- Latest user override: do not stop manufacture or execution at a fixed token allowance. Retain token metering for efficiency comparison, not authorization. Revise legacy token-budget APIs/tests and distinguish provider protocol/context constraints from product budgets. Money/time controls remain separate.

### Phase 6 design decisions

- Keep the game domain independent of strategy. An optional preset hint names only a registered preset; a trusted compiler allowlist restricts runtime game manufacturing to the three game strategies. Neither setting grants capabilities.
- Local tests use three rule families and globally disjoint canonical puzzle instances for parent training, parent held-out, child support and delivery. They do not measure unseen-rule generalization or official ARC performance.
- Nested factory results report aggregate usage; raw telemetry still bills each model call once. Official score finalization stays inside the execution deadline. Separate judge grading cost remains compilation overhead, not agent delivery cost.

- Official score policy `relative_human_action_efficiency.percent.v1` is pinned to arc-agi 0.9.9 / arcengine 0.9.3. Only completed-card numeric percentages in 0..100 are normalized by 100. Per-level 1.15 does not change the final scale. Documentation fixtures and synthetic boundary tests are not live benchmark evidence.
- Official OFFLINE development uses explicit pinned preview manifests and separate repeatable episode scorecards. Full public base-game identities are disjoint across roles. A submission gateway's single-card/all-games rules do not apply to development tuning; gateway providers are rejected for candidate trials.
- HTTP compilation checks both returned and persisted report identity. Freshness snapshots defend against stale compiler results, not hostile privileged host code. Private catalog metadata cannot select arbitrary registry names or expose artifact paths.

### Phase 9 design decisions

- Sandbox language v2 supersedes the Phase 4 loop ban for v2 only: "no unbounded loops" becomes "loops only in language v2, and only under fuel", and the comprehension ban stays. Language 1 is frozen (same grammar, semantics and `artifact_digest` for every artifact with `forge is None`); language 2 is selected only by an artifact's `ForgeBinding`, never by the source text.
- v2 drops the static count of 64 await sites, because loops make a static count meaningless. The dynamic per-run op cap `call_limit(artifact)` (from the binding: 128 by default for text, `max_turns * calls_per_turn` for games) is the authority; `call`, `preset`, `harness` and `step` count, `observe` does not.
- The Phase 8 rejection of `images=` in sandbox calls is reversed for v2 only; v1 still rejects it. Images still never cross the pipe: v2 source names `$image` stubs from `task`, and the host resolves their sha256 against the run's own attached images.
- Forge label visibility is a deliberate, Forge-only exception: the agent sees tuning inputs and, in `per_case` feedback mode, truncated tuning expected values, and never any held-out case, id, count, score or report. `feedback="aggregate"` restores Stage 3's no-labels behaviour, and `rewrite()` keeps its no-labels prompt.
- Forge accepts a submission by `forge_rank` (contract Section 8.8): floor passed, budget passed, smoke not failed, then higher tuning score, lower mean cost, fewer components and sub-harnesses, fewer nodes, against the Stage 2 best measured the same way. Unlike `_cheaper` it accepts a quality repair that costs more; `rewrite()` and `_cheaper` are unchanged for non-Forge compiles.
- A child sub-harness is licensed by its own Stage 4 on its own odd half of cases drawn only from parent tuning (`projection`) or agent-authored data (`authored`), recorded as `case_origin` in `SubharnessRef`, `forge.json` and the docs. No parent held-out case ever reaches a child floor, so a child license carries no parent held-out information and is weaker than a parent license; only the parent's Stage 4 licenses the task.
- `GameFactoryConfig.allow_forge` (default False) is the only way a game factory accepts a sandbox artifact, and only one that carries a `ForgeBinding`; without it the factory still refuses with `game_sandbox_forbidden`.
- With Forge enabled, the outer compile wallet is raised by exactly the Forge budget (`compile_budget + Budget(forge.max_usd, forge.max_s)`), so Forge cannot be starved silently by an ordinary compile budget. The summed cap is shown before any spend and needs operator consent (`Continue? [y/N]`, `--yes`, or the session confirmation); Forge's own nested wallet still caps the session.
- `forge_submit` runs a literal-leak lint: any string constant or f-string literal part of 24 or more characters that equals or contains a tuning input or expected string leaf (or canonical expected JSON) of that length is rejected with `forge_literal_leak`. Tuning-derived few-shot literals are therefore out of scope in Phase 9.
- Every v2 capability RPC costs fuel (64 plus 1 per 8 bytes of JSON sent and received), on top of 1 per evaluated node and builtin work, so fuel also bounds how many host round trips a loop can make, and with it wall time, even in a loop that mostly waits on the host; the unchanged run deadline remains the outer bound.
- The smoke floor of a Forge game compile is built only from the public support-tuning games (`support_smoke_floor`), never from support held-out, delivery or target games, so Forge's smoke gate cannot see any partition it is not allowed to tune on.

### Phase 10 design decisions

- Routing orders licensed versions and never licenses. A `RouteDecision` holds references only (`name@revision` and digests, or a library key); every execution re-loads the artifact from disk and re-checks license, digest, spec hash, slot and consumption (`load_reuse_target`), and `Runtime.run` re-checks the license again. No routing component writes `approved=`, a report or a signature, or calls `Registry.install`.
- The default experience is unchanged. `Services.router` exists with the contract default `RoutePolicy()` (for `architect route`, the session `route` verb and `POST /route`), but a compile routes only when the profile declares a `routing` table, or when the operator grants installed reuse for that one call (`do --reuse-installed`, session `reuse`, `route --run --yes`, `forge run|integrate --reuse-installed`). `--no-route` compiles exactly as a Compiler without a router.
- The default role policy `pinned` is byte-identical to Phase 9: every role call uses today's adapter, and the Forge consent of `compile`, `recompile`, `do`, `create` and the session prints the Phase 9 cap line alone. Under `evidence` the `forge agent:` line is chosen and printed immediately before it. `forge run` and `forge integrate` always print it (new commands).
- `refuse` (no configured ladder model) keeps the existing compile path; `route_no_candidate` is appended only to a failed result, so a routing refusal can never block a compile that would succeed. A granted reuse whose target changed returns the route code (`route_target_changed`, `route_unlicensed`, `route_consumed`) and runs nothing.
- The compiler records one content-free `OutcomeRecord` after Stage 4, except for `forge_integrate`, which records its own outcome (no duplicate). Routing and role records are fail-open (P5).
- The session's single approval expression is `services.compiler.compile(spec, approved=self.approved(spec), origin="session")`, so session compiles route with the `session` origin: only `session` in `routing.reuse_origins` (or the typed `reuse <name> <hash8> {json}`) reuses an installed entry in a session, and a `cli` grant never reaches it. A test greps the expression.
- A recompile never reuses (Phase 10 Section 8.5: the `route_promote_proposed` command is `architect recompile`, and only a Stage 4 in that call may replace the incumbent). `architect recompile` passes `allow_reuse=False`; the session keeps its single approval expression unchanged and creates the `recompile <name>` compile task inside `architect.compiler.recompiling()`, a context mark that the next `compile` consumes (nested Forge compiles are not marked). Both still route, so a recompile may warm-start. Without this, a standing `cli` or `session` grant handed the incumbent back as `accepted, reused, stages []`.
- Before Phase 10 the words `route`, `reuse`, `roles`, `export` and `rate` were prose. `commands.parse` keeps a line starting with one of them as prose in every state that does not offer that verb, and in READY accepts only the exact shapes `roles`, `rate`, `rate good` and `rate bad`, so a default-profile goal such as `route support tickets to the right team` is still inferred.
- The bench CLI runs the routed arm (`bench run --variant routed [--rounds R]`), exits 1 with `route_did_not_run` when a routed row has it, and replays the committed fake role logs with `bench roles --policy pinned|evidence`. The smoke baseline's routed rows can only come from the Linux CI job: page manifests of the image tasks differ by platform, so rows produced on Windows never pair (`bench_compare_mismatch`).
- The Tier A key compares latency at 0.1 s resolution (`router.LATENCY_RESOLUTION_S`, floored). A measured median below that is clock-tick noise (15.6 ms ticks on Windows, sub-millisecond fake runs elsewhere): with raw values, two identical smoke runs chose different tied Phase A arms (`default-` vs `template-<task>`), failing pass criterion 4 (identical decision sequences). Ties below the resolution fall through to `k`, then the categorical name.
- A delivery step honours exactly the grant the router reused under: the per-call grant or the profile's `routing.reuse_origins` entry for that origin (`orchestrator`, `forge_run`, `forge_integrate`). A profile grant therefore delivers the reused entry instead of failing the task after the compile already reused it.
- A reused result (`CompileResult.reused`) is never installed again: `cli._compiled` skips the install, the session refuses `install <name> <hash8>` with `route_reuse_installed` (and remembers the entry for `export`), and the FeatureBuilder's `compile_agent` returns the reused entry itself (`code: route_reuse_installed`).
- The `forge_agent` role is chosen exactly once per consent. The session's Forge-mode consents are asynchronous while the Forge-mode APIs take a synchronous `consent` callback, so the session resolves the role with `prepare_agent` (no dry call), shows that text, asks, and passes the same `AgentChoice` to `forge_run`/`forge_integrate` (`agent=`), whose text is then identical. A refusal records the choice as `excluded` (an operator cancel). `forge integrate` in the session stages first, asks the export consent itself, then places through the FeatureBuilder/Pi path and re-hashes the placement against the manifest the operator consented to (`placement_codes`, shared with the CLI path), also checking pins, children and, with the key, the license.
- A compile-path `forge_agent` choice (CLI `compile|recompile|do|create --forge` and the session under `roles.policy = "evidence"`) gets its Section 11.4 outcome after the compile: `success` when Forge's accepted submission was licensed, `failure` when Forge ran otherwise, `excluded` on an operator cancel or when Forge never ran (`trigger=failed` and Stage 2 passed). The pinned default records nothing and prints byte-identically.
- Two additive result fields: `ForgeRunResult.run_id` (the delivery's UUID, so the session can `rate` it) and `IntegrateResult.build_cost_usd`/`compile_cost_usd` (honesty rule 8; `forge integrate` also prints `forge integrate: ... build $A agent (API-equivalent), compile $B, play $0.0000 (nothing is run)` on stderr). `rate good|bad` is allowed in READY, REVIEW and RESULT, because `reuse` and `forge run` deliver in REVIEW.
- Explanations are wrapped at 100 ASCII columns, never cut: the route decision line wraps between whole codes, `route` screens print each code's fixed Section 13.4 sentence and the command that acts on it, and the CLI wraps its Forge-mode stderr lines as the session does. The Phase 9 `compile --forge` cap line under `pinned` is unchanged.
- `architect export verify --reverify` never executes code shipped in the package. It first requires the package's own integrity, pin and children checks to pass (else the first of `export_integrity_mismatch`, `export_pin_mismatch`, `export_subharness_missing`, before the consent line), then re-runs Stage 4 of the approved Spec on a private copy, under the workspace artifact root, of this host's own installed entry with the same artifact digest and spec hash. A package this host never installed is `export_unverified`: another host mints its own license only through `architect compile --approved-spec <package>/artifact/spec.json`. The package is never written and a failure deletes nothing. It is bounded by `max_verifications_per_spec`.
- `route --run` executes an installed harness only with the per-call `--yes`; a standing `cli` entry in `routing.reuse_origins` does not run one without it (`route_no_reuse`, nothing is routed or run).
- Session `forge integrate` binds the export consent, FeatureBuilder's check and the post-placement re-hash to the `manifest_sha256` that `forge_integrate` returned when it staged the package; a staging copy changed since (even repacked self-consistently) is `export_integrity_mismatch` and nothing is placed. On a lifecycle-expire Spec it answers `approved_feature_must_be_installed` with the hint `set lifecycle install, then approve <hash8>`, before any approval hint, and the `route_forge_suggested` advice for an expire Spec says `forge on, then compile` and names `set lifecycle install` for integrate.
- A standing-grant reuse approve prints a routing banner (`routing <hash8> to installed <name>@<rev>  no Stage 1 to 4 and no compile spend`, then the budget a changed route would compile within) instead of the compile banner; the COMPILING prompt is unchanged (Section 4 fixes the prompts). A cancelled session `forge run` or `forge integrate` build prints the compile cancel summary and one footer; a quit leaves the footer to the exit.

### Forge pack v2 decisions (2026-10-04)

- Sandbox language v2 only grows: it now accepts type annotations (ignored, never evaluated, and only shaped like a type), defaults that are literals or constants (copied for each call), variables and parameters named like builtins, the builtins' method spellings (`s.split(sep)`), `isinstance` with type names, `get` and `at` without a default, and module constants as `execute_preset` binding arguments. Every source v2 accepted before still validates and runs the same way, so the version stays 2. The accept or refuse decision for each construct the G1 sessions were refused for is in `docs/interfaces/phase9-forge.md` Section 4.14.
- Every static refusal names a rule from `sandbox_language.RULES`. The Forge tools show it with the line and one or two fixed sentences giving the allowed form, built only from fixed tables, so no source text is ever echoed. The tables are part of the Forge pack hash (`prompt/refusals`).
- The language card ends Forge's system prompt (`forge_prompt`) as well as being `LANGUAGE.md`. The parent's context cap drops the oldest tool results first, so a read of LANGUAGE.md was the first thing to go; in G1 the Ultra engineer re-read it up to 14 times. A system prompt is never thinned.

### Forge pack v3 decisions (2026-10-04)

- One check lists every refused line. Past parsing, the language 2 check records each refusal and keeps going, and the Forge tools return them all (`refusals`, by line, at most 20, each kind once before any repeat, a repeat shown as "Line N: the same problem as line M."). In the G1 retry each check named only the first refusal and Ultra fixed one line per round. Messages still come only from fixed tables and line numbers.
- Comprehensions are accepted, reversing the Phase 4 ban kept in v2. The check desugars each into the for loops it stands for, run in place with a scope of their own, so a comprehension costs exactly its loop's fuel and copies (tests compare the two forms) and its names never outlive it. A set comprehension gives a list without repeats in first-seen order. A generator expression is accepted only as the list argument of any, all, sum, min, max, sorted, list or join, where it is the last thing the call evaluates. `any` and `all` became builtins, the one change that refuses source v2 accepted before: a helper named any or all.
- An `if __name__ == "__main__":` block at module level is dropped at check time, unread; nothing in it runs. Any other module-level if is still refused.
- No module is ever imported. An import of a module Ultra used (json, re, typing, dataclasses, enum, asyncio, architect, forge) or of a few common ones gets a refusal that names the builtins replacing it, and so does every read of a name that import bound. There are no regular expressions, so `re` maps to the string builtins.
- `run` keeps one form, `async def run(context, task)` with any type-shaped annotations; any other first line is told the exact line to write.
- The spend relay's per-model limiter defaults to 90% of Token Factory's published limits (was 50%), and a settled call counts only its uncached prompt tokens plus its completion toward the token budget (`limiter_counts_cached_tokens` restores the old count). In the G1 retry the relay held Ultra to about 3.5 turns a minute with 55 of its own 429s per session.

### Forge pack v4 decisions (2026-10-05)

- The context cap's note for a trimmed write or edit text no longer stands in for the text ("[8737 characters, removed ...]"): it says it is not file content and to read the file. With the parent cap on, a write or edit whose text holds any of the cap's notes, old or new, is refused with that advice, so a pasted note never reaches a file. In the bake-off Super pasted the old note into harness.py 43 times and lost the last 62 turns of its session.
- Accept-only language additions, task-neutral and with no new capability or regular expressions: typed and named excepts (one except still; any type catches every data error and never a fatal one; `e` is the error's code while the handler runs, then unbound, as in Python), three loop names for `zip` of three lists, the character tests, `chr`, `ord`, `split()` on whitespace, `strip`, `lstrip` and `rstrip` with characters, `rfind`, `copy`, and `min` and `max` of two values. Each is metered exactly (tests compare `max(a, b)` with `max([a, b])` and `l.copy()` with `list(l)`, and assert every other charge), and the quadratic ones (`rfind`, `strip` with characters) pay their CPython worst case before the work. As in v3, the new builtins' names can no longer name a helper; no kept draft or template does. The details are in `docs/interfaces/phase9-forge.md` Section 4.16.
- DESIGN.md says that when code can read a field exactly from the input, code's value is final for that field, and the model is asked only for what code cannot decide. In the ceiling diagnostic, code reading the amounts took the preset from 0.22 to 0.48 on practice receipts (in-sample, development only).

### Nebius role pack (2026-10-05)

- A fresh Nebius profile's Forge engineer is Super with thinking off at temperature 0 and 300 s a call, the setup of the last Forge round, where it was Ultra with thinking on. ### Default engineer on Token Factory (2026-10-05)

- When Forge's engineer would be a Token Factory model, with a judge code or the user's own key, a build ships the tuned preset unless the user chooses Forge (`default_engineer` in `architect/agent/build.py`). Forge had no harness accepted with a Nemotron engineer in 12 sessions (5 with Ultra, 7 with Super), the last of them inside the evidence build, where Forge spent $1.16 of its $1.20 and 27 of the build's 40 minutes (`examples/bench/eval-2026-10-05/ladder/outcome.json`). Other providers keep Forge as the default.
- A fresh Nebius profile caps Forge at $1.20 and 45 minutes (`NEBIUS_FORGE`), so a Forge session the user turns on fits in one $3 day of a judge code.
