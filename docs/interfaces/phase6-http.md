# Phase6 HTTP and TypeScript contract (planning; Phase5 gate first)

The HTTP service is a trusted local control plane over existing Services. It does not accept model/evaluator profiles, credentials, artifact paths, reports or licenses from request bodies. Bind loopback by default. Require an operator-selected bearer token; never put it in telemetry or browser bundles. Access logging is off by default. All errors are fixed codes; do not expose exception text. Only Compiler Stage4 licenses. No token quotas.

Implement architect.server.create_app(services:Services, *, api_token:str) -> FastAPI; injected Services remain caller-owned. Add a CLI/main helper for loading a trusted local profile and owning cleanup. Five operations only (Phase 10 amended four to five by adding POST /route):
- POST /compile: {request?:string, spec?:Spec, approved:boolean=false}; exactly one source. Calls real compiler. Installed proposal returns spec + approval_required, not an artifact. Approved install must use exact explicit spec (approved=true with inferred request is rejected). On verified installation call Registry.install; never silently replace worse/equal entries. Return CompileResponse {accepted, approval_required, spec, artifact_id:null|string, failures:string[], stages:number[], warm_started:boolean}. No private paths/signing material in DTO.
- POST /run: {artifact_id:string, input:JsonValue, enabled:boolean=false, human_reviewed:boolean=false}. Resolve a server-owned opaque ID; no user paths. Installed delivery requires both explicit flags; ephemeral delivery retains one-shot semantics. Authenticate current persisted artifact and Runtime.run, never model approval. Return {run_id, output, tokens_in, tokens_out, cost_usd, wall_time_s}. Tokens measured only. This API is for a trusted backend, not direct untrusted browser access.
- GET /status/{artifact_id}: {artifact_id, licensed, expired, lifecycle, spec_hash, version, registry_name?:string}. Recheck persisted authentication. Must work after server restart and explain expired artifacts without granting execution.
- POST /recompile: {artifact_id:string}. Only installed existing agents; use the original approved Spec and fresh Stage4, then Registry acceptance. Do not broaden spec/tools/floor/budget through this API. Return same CompileResponse; worse/tied replacement fails and prior pointer remains.

Server persists opaque-ID mappings under services.workspace/server/ (atomic SQLite or equivalent); protect that directory through effective Pi denied_paths. Treat mapping as private host state. Resolve/catalog paths against configured artifact/registry roots, reject traversal/symlink escapes. Do not trust an artifact merely because it appears in the mapping. Existing Registry and Runtime gates remain authoritative.

TS package client-ts exposes exactly compile, run, status, recompile, route (class/factory initialization is allowed). Constructor accepts baseUrl and bearer token; DTOs typed, generic JSON values, no token Budget field. Use native fetch, no extra workflows. Tests use a mocked local HTTP server. Build with tsc; node --test acceptable. API rejects nonfinite/malformed/extra authority data and surfaces bounded fixed errors. No automatic install approval or enabled/reviewed flags. An explicit local live-server end-to-end test must compile and run an example with fixture-only authorization flags.

Docs must distinguish a spec approval from production deployment readiness. Examples remain feature-flagged and human-reviewed; no one-month production cost/edit-rate evidence is fabricated.

Implementation safety details: authenticate before parsing request bodies. Disable automatic OpenAPI/docs routes so only the five declared operations are exposed. Replace validation responses with fixed error codes; default FastAPI validation details can echo private request content. Bound request bodies and identifiers. Compare bearer tokens without exposing them in logs. Start the supplied server helper on loopback with access logging disabled.

## Phase 10 amendment: POST /route (advice only)

- POST /route: body `{"spec": Spec}` only. A missing Spec or a prose `request` is 400 `route_spec_required`. It spends $0 and runs no Stage 0, no execution and no exploration; the origin is `http` and reuse is never granted. Response `{action, artifact_id, fit_tier, fit, quality_lcb, expected_cost_usd, latency_s, latency_basis, evidence, codes}`: closed labels, numbers and fixed codes only, never names, paths or text. `artifact_id` is set only when the catalog already knows the Tier A target (`catalog.find_installed`); otherwise it is null with `route_not_catalogued`.
- Routing orders licensed versions and never licenses: Stage 4 alone licenses, and `/run` is unchanged (installed runs still need `enabled` and `human_reviewed`). There are no HTTP Forge endpoints.
- `_FAILURE_CODES` gains `route_spec_required`, `route_no_candidate`, `route_unlicensed`, `route_budget`, `route_drift`, `route_model_unconfigured`, `route_not_catalogued` and `evidence_store_unavailable`.
- HTTP compiles use the `http` origin (advice-only for reuse, never exploring); they route only when the profile declares a `routing` table.
- client-ts gains `route(spec)` with typed `RouteRequest`/`RouteResponse` DTOs; a prose request is a type error and a runtime `INVALID_REQUEST`.
