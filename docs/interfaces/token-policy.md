# Token policy update — latest user direction overrides earlier phase contracts
User: "Token bounds shouldnt be a thing - it should just manufacture EFFICIENT agents not limit itself by a set token amount".

## Required behavior
No per-agent, per-run, compiler, orchestrator, pipeline-step or installed-version TOKEN quota. Token use is observed data and an efficiency objective, NEVER a stop/licensing/acceptance condition. Dollar/time safety controls remain separate and unchanged. Optimize actual cost, token efficiency where dollars are zero, and structural simplicity subject to quality. Do not manufacture efficiency by clipping every response to an arbitrary small token count.

Budget has ONLY cost_usd and compute_s fields. For compatibility, a before-validator silently discards a legacy input key tokens (does not serialize it or expose it in generated schema). No Budget.tokens attribute. All counters/report tokens/mean_tokens/max_tokens stay as measured metadata. CompileWallet.tokens is a USAGE counter, not a remaining allowance. Only dollars/time exhaust wallet; a response exceeding estimated token counts is reconciled, not rejected, provided dollar reservation is respected. Report licensing never compares tokens against a budget. Registry replacement never compares token ceilings. Orchestrator/pipeline only clamp dollars/time.

Provider limits are not product budgets: ModelRequest.max_output_tokens becomes int|None defaultNone. Normal factory/preset/Pi calls pass None, not128/4096/8192 manufacture quotas. When provider API requires max_tokens, use configured model output capacity; OpenAI/Ollama may omit optional output caps, with conservative model-capacity cost quote where needed. Capacity is provider/protocol metadata, NOT artifact budget, and must be documented/configurable rather than falsely presented as unlimited provider context. Explicit legacy positive max_output_tokens is still accepted as a low-level provider request option, but preset search no longer tunes it as an efficiency quota. Model token counts must remain accurate. Dollar preflight stays conservative; explain insufficient-money refusal rather than silently reducing quality. Memory/byte/protocol/depth/tool-turn/rewrite caps remain safety bounds, not token quotas.
