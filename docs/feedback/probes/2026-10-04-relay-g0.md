suite passes, one live call succeeds, a code over its cap gets a 402, and a model outside
`nvidia/*` is refused. This note records that run on the local host
(`deploy/relay/local.mjs`), plus one call that Architect itself made through the relay.
No access code and no Token Factory key appears in this note.

## Summary

- G0 passes its same-day checks on the local host. The suite passed (225 tests, 1
  skipped), and every live check below matched what the relay's README says it does.
- Five calls reached Token Factory, all on Lightning. Each one was settled from the usage
  Token Factory reported, streams included. None was booked at its full hold or released.
- The refused calls (403, 401 and 402) wrote nothing to the ledger and left no hold.
- Live spend: $0.00029688 at list prices. Of that, $0.00029016 is the one call made on
  purpose to use up most of a $0.0005 code.
- Still open: the owner reads the Token Factory console on 2026-10-05. The ledger must be
  at or above what was billed, and within 5% of it.

## Notes

- For the same 8-token Lightning request, the time to Token Factory's response headers
  (`x-upstream-ms`) was 3.4 s for the whole reply, then 11.7 s and 1.2 s for the two
  streams. These are single calls, not a latency measurement.
- The ledger total so far is $0.0003, which the console may round away. The pilot's
  spend goes through the same ledger and gives the first comparison worth making.
- The ledger counts list prices, with cached input at the full input price. If Token
  Factory bills flex or cached tokens for less, the ledger will read above the bill. The
  replies whose usage the client saw (checks 1, 3 and 7) reported no cached tokens.
- R2 (a 4xx that comes after generation is released, not booked) and R4 (ledger commands
  spent while a call waits for the limiter) are still pinned as expected failures in the
  suite. R4 costs only Upstash commands. The known R2 case is a reply with tools and
  `tool_choice` `required` that `max_tokens` cuts short, and the evidence arms send no
  tools.
